## Findings

### N1 (H) Results are placed by count, not by slot, so one unmatched link promotes every winner below it, with the wrong amount
- **Where:** `ingest/src/results.mjs:99` (ambiguous or unknown prefix → `unmatched`, no slot kept) and `:146-156` (`place` derives from how many hits came before).
- **What's wrong:** The real results posts label each place: "1st place ($1,024): …", "2nd place ($512): …", "Honorable mentions ($128 each): …". The parser ignores those labels. If the 2nd-place entry was never captured as a submission, the first honorable mention becomes "2nd" and gets the 2nd-place amount. That can happen when the entry is a quote cast, a nested reply, or on an unlisted host such as Vimeo, TikTok or Loom. An ambiguous 8-hex prefix does the same. The results go into `book.json`, and winners are marked on submissions. A warning is printed only when the post replies to or quotes the prize; for a top-level results post the shift is silent.
- **Repro:** `node /tmp/review-tools/adversarial.mjs`. The same as a one-liner against the seed:
  ```js
  parseResults("Thank you to everyone who submitted!\nfarcaster.xyz/papa/0x780d71e5\nfarcaster.xyz/zatweirdaj/0xdeadbeef\nfarcaster.xyz/tophb/0x894be0b8", civilitySubs, { pool: civility.pool })
  // → [["1st","$1,024","@papa"], ["2nd","$512","@tophb"]]   tophb was an honorable mention ($128)
  ```
  The same happens when the first link is an ambiguous prefix: the 2nd-listed entry is recorded as 1st with $512.
- **Fix:** Take the place from the label on the link's line or section, or keep a slot for every link, matched or not. Never record results for a prize while a post that replies to or quotes it has unmatched links.

### N2 (M) A deleted or retracted entry never leaves the book
- **Where:** `ingest/src/refresh.mjs:140-145`. Every submission in the previous build is carried forward forever, and nothing reconciles it against the current reply listing.
- **What's wrong:** If an author deletes their reply, or a spam reply is removed, Primer keeps showing it among the voices indefinitely, including while the prize is still re-read every 30 minutes. The only way to remove it is to delete `content/build/book.json`.
- **Repro:** `node /tmp/review-tools/deleted.mjs`:
  ```
  run 1 (entry live): refresh: wrote …/book.json | entry in book: true
  run 2 (entry deleted on the network): refresh: unchanged, not written | entry in book: true
  ```
- **Fix:** When a prize's replies are re-read and the listing is complete (`truncated === false`), drop carried non-seed submissions for that chapter that are missing from it.

### N3 (M) An award or winners announcement with "PRIZE" in caps becomes a new prize and a public draft idea, with an open countdown
- **Where:** `ingest/src/detect.mjs:14` (`CAPS_PRIZE = /\bPRIZES?\b/`) and `:48`.
- **What's wrong:** Any caps "PRIZE" in the first line makes a watched author's top-level cast a `kind: "prize"` with a 3-day deadline and a "New pick · just dropped" draft. The real "THE FARCASTER PRIZE" cast (`0xf454b8d3`) is an award announcement, and it avoids this only because the seed overrides it. The owner said more such awards would follow. A winners post that does not start with "Thank you to everyone who submitted" is caught the same way. This follows SPEC's "contains PRIZE", so the spec rule is too broad.
- **Repro:** `node /tmp/review-tools/award.mjs`:
  ```
  {"text":"THE SECOND FARCASTER PRIZE","isPrize":true,"kind":"prize","id":"second-farcaster-prize","deadline":"2026-11-15T10:00:00Z","draft":{"title":"Second Farcaster Prize","status":"draft",…}}
  {"text":"TIEBOUT PRIZE WINNERS","isPrize":true,"kind":"prize","id":"tiebout-prize-winners",…}
  ```
- **Fix:** Planner: tighten SPEC. Ingest: a caps-PRIZE match with no `$N … FOR` or "$N PRIZE" should become `kind: "announcement"` (no draft), or require a submission phrase ("reply with", "runs for N days").

### N4 (M) A 4xx is never failed over, so one rate-limited node fails the whole run even when the next node is healthy
- **Where:** `ingest/src/node.mjs:87-90`.
- **What's wrong:** A 429 from a public node, or a 404 or 400 from a node that is lagging or pruned, is surfaced as `NodeHttpError` and no other node is tried. Fail-closed still holds (exit 1, nothing written). But the endpoint fallback in I1 is defeated by the most common way public nodes fail. A scheduled job pinned to a rate-limited first node fails every 30 minutes.
- **Repro:** In `adversarial.mjs`, the first node answers 429 and the second answers 200:
  `NodeHttpError: …answered /v1/castsByFid?fid=1 with HTTP 429 … — second node requests: (not contacted)`. A 404 on `castsByParent` behaves the same.
- **Fix:** Treat 408, 425 and 429 (and 404 on list endpoints) as `Failover`. Keep other 4xx as answers.

### N5 (M) On build prizes, any non-platform link counts as a "microsite" entry
- **Where:** `ingest/src/classify.mjs:135` and `siteUrl()` (`:224`).
- **What's wrong:** A reply such as "great read https://www.theblock.co/news/x" on a build prize becomes `{kind:"site", gloss:"Build entry: theblock.co"}`. So does a link to someone's blog or a portfolio. Only the promo-word list filters these out. SPEC says "a microsite or repo URL", and "everything else is conversation".
- **Repro:** `adversarial.mjs`, case "build: html in text + news link".
- **Fix:** A reply with a site and no repo should count only with entry words ("submission", "entry", "built", "quickstart") or a vouch link.

### N6 (M) URLs are kept verbatim, with markup characters and no length limit, and the contract accepts them
- **Where:** `ingest/src/text.mjs:140` (keeps "the exact string the author wrote"), `ingest/src/classify.mjs:283`, and `contract/validate.mjs:67` (only `^https://[^\s<>"']+$`).
- **What's wrong:** These pass `validateSubmission` and `validateBook` and land in `embeds`, `site` and `repo`:
  - `https://evil.example/a)](javascript:alert(1`
  - `https://evil.example/{{sub:0x1}}/*x*/[a](b`
  - a 10,021-character URL

  A renderer that ever builds an Inline string from them, such as `[site](${s.site})`, would be injectable. A few hostile replies can also inflate `book.json`, which is inlined into the artifact and has a 3 MB limit (W4).
- **Repro:** `adversarial.mjs`, cases "build: url with quote+paren", "url with markup chars", "10k-char site url". The compile result is `validateBook: []`, `maxEmbedLen: 10021`.
- **Fix:** Re-serialize with `new URL(u).href`, reject URLs containing `()[]{}*` or longer than 2048 characters, and add the same length cap to `validateSubmission` (planner).

### N7 (M) The I6 proof is regex-based and most workflow mutations survive
- **Where:** `ingest/test/refresh.test.mjs:259-273`, for example `:264`, where the regex is not anchored.
- **What survives** (scratch mutants, full suite run each time):

  | Mutant | Result | Effect if shipped |
  | --- | --- | --- |
  | `run: … --now "$(date…)" --offline` | **SURVIVED** | Offline always writes, so it commits every 30 min and drops every item fetched earlier |
  | `git commit -am …` | **SURVIVED** | Commits any tracked change, not only `content/build/` |
  | `continue-on-error: true` on the refresh step | **SURVIVED** | Failures are hidden |
  | `concurrency:` block removed | **SURVIVED** | Overlapping runs |
  | `git push --force` | **SURVIVED** | Can clobber main |
  | heartbeat removed (`&& !stale`) | **SURVIVED** | Provenance goes stale |
  | CLI writes `{}` before rethrowing a compile error | **SURVIVED** | Partial write on an invalid book |

- **Fix:** Anchor the run-line regex (`…%TZ\)"$`), assert that no `commit -a`, `--force` or `continue-on-error` appears, assert the `concurrency` group, and add a CLI test where an invalid chapter file leaves the previous `book.json` byte-identical.

### N8 (L+) Rules in I1–I5 that no test protects (mutants survive)

| Row | Mutant | Why it survives |
| --- | --- | --- |
| I1 | The CLI builds its client with a 60 s timeout | Only the exported constant and `createClient()` default are tested, not the refresh path |
| I1 | A 4xx on `castsByParent` is recorded as zero replies | No test exercises a 4xx on replies. This is the spec's "never as zero submissions" rule |
| I2 | The headline regex is applied to the whole text instead of the first line | No fixture has a prize phrase below line 1 |
| I2 | A reply to the *other* watched fid counts as top-level | No fixture covers it |
| I3 | `stream.farcaster.xyz`, `media.firefly.land` and `video.bsky.app` host rules removed | Every test URL also ends in `.m3u8`, so the suffix rule hides the host rule |
| I4 | An ambiguous hash prefix takes the first candidate | There is no ambiguous-prefix case, even though the code has a branch for it |
| I4 | The prefix is matched anywhere in the hash | No negative case |
| I5 | No tie-break after `postedAt` | No equal timestamps in the data |

- **Fix:** One small test per row: host URLs without `.m3u8`, two submissions sharing an 8-hex prefix, a 429 on replies leaving the previous file untouched, and two submissions with the same `postedAt` given in both orders.

### N9 (L+) Replies are not checked to be replies to the prize
- **Where:** `ingest/src/refresh.mjs:166`. `classifyReply` never checks `castAddBody.parentCastId.hash === prize.castHash`.
- **What's wrong:** A stale, buggy or hostile node can return any casts for `castsByParent`, and each one that has a video becomes a voice on that prize. The README says ingest trusts its nodes, and the first default node is a third-party Hypersnap fork, so a one-line guard is worth having.
- **Repro:** `adversarial.mjs`, "castsByParent returns a cast whose parent is NOT the prize" → `{"classified":"video"}`.
- **Fix:** Skip messages whose `parentCastId.hash` is not the prize hash (and, for `castsByFid`, whose `data.fid` is not the requested fid).

### N10 (L) Test fixtures pair real cast hashes with invented text
- **Where:** `ingest/test/fixtures/casts-fid1.json`. The bodies of `0x2ba04801` and `0x287c8ebe` say "Book club pick #2:" and "#1:", and "Submissions close in three days".
- **What's wrong:** The real casts say neither. They say "think of this as an interactive book club" and "This prize runs for three days exactly from this post's timestamp" (WebFetch of `castsByFid?fid=1`). `detect.test.mjs:140` asserts the series "Book club pick #2" from the invented text, so a live run on a new pick will produce "Book club" with no number. Deadlines still parse, because the real text also contains "three days". The headline test only proves the headlines are real.
- **Fix:** Paste the real cast bodies into the fixtures (they are public), or mark the fixtures as synthetic and keep one real body per prize.

### N11 (L) Offline builds record provenance as if the nodes had been read
- **Where:** `ingest/src/compile.mjs:240`, `:261`.
- **What's wrong:** `/tmp/review-book.json` (offline) lists `provenance.nodes: ["https://haatz.quilibrium.com","https://snap.farcaster.xyz:3381"]` and `refreshedAt: 2026-11-12T19:30:00Z`, although no node was read. The note says "Read from public Farcaster protocol nodes".
- **Fix:** In offline mode, write `nodes: []` and carry `refreshedAt` from the previous build, or from the seed date.

### N12 (L) Network prize headlines are kept raw
- **Where:** `ingest/src/detect.mjs:139`.
- **What's wrong:** `deliverable` goes through `plain()`, but `headline` keeps `<script>…`, `{{sub:0x…}}` and `[x](javascript:…)`, and so does `context.headline` (`refresh.mjs:129`). `validateBook` passes because `headline` is not an Inline field. Only watched authors can post prizes, and renderers must escape anyway (contract), so the risk is low; the treatment is inconsistent.
- **Repro:** `adversarial.mjs`, "book with hostile prize". The draft title becomes `‹script›alert(1)‹/script›…`.
- **Fix:** `plain()` the headline in `derivePrize`, as is already done for the deliverable.

### N13 (L) Workflow details
- **Where:** `.github/workflows/refresh.yml`.
- **Queued runs and rebase:** The refresh job uses the default checkout, which is the trigger SHA (`:29`). A run that waited behind another run that pushed starts from a stale `book.json`, and `git pull --rebase` then conflicts on it. The job fails (bash `-e`, nothing pushed). That is safe but noisy. **Fix:** use `ref: ${{ github.ref_name }}` in this job too, or `git fetch` and reset before refreshing.
- **Hardening:** `persist-credentials` defaults to true, so the write token sits in `.git/config` while untrusted network data is processed. **Fix:** set `persist-credentials: false` and push with an explicit token.
- **Pinning:** Actions are pinned to major tags, not commit SHAs.
- **Leftover temp file:** A crash between `writeFileSync(tmp)` and `rename` leaves `book.json.tmp-<pid>` in `content/build/`, and `git add -- content/build/` would commit it. **Fix:** write the temp file outside `content/build/`, or `.gitignore` `*.tmp-*`.

### N14 (I) The refresh runbook and SPEC no longer match ingest (planner)
`docs/REFRESH.md`:
- `:35` uses only "contains `PRIZE`", without the 2024 headline forms ingest needed.
- `:44` says "below 99", but the coda is now 999.
- `:64` says "up to 5 pages", but ingest reads 10.

The overlay job and the Action can therefore disagree about which casts are prizes. Also, `contract/fixtures/book.sample.json` still numbers the coda 99.

## Workflow review

- **Permissions:** Top-level `permissions: {}`. The refresh job has `contents: write` only. The deploy job has `contents: read`, `pages: write` and `id-token: write`. **OK.**
- **Injection:** No untrusted text reaches a shell. The only expansions are `$(date -u +%FT%TZ)`, the quoted `$GITHUB_REF_NAME` and `$GITHUB_OUTPUT`. The commit message is fixed, and no `${{ }}` expressions are interpolated into `run:`. Network data reaches only Node, which never executes it. **OK.**
- **Nothing to commit:** `git status --porcelain -- content/build/` is empty → `changed=false`, exit 0. Deploy is skipped on schedule and still runs on `workflow_dispatch`. Unchanged online runs write nothing, except the 24 h heartbeat, which commits and deploys once a day. **OK.**
- **Concurrency:** `group: refresh`, `cancel-in-progress: false`. Runs, deploy included, never overlap. A run queued behind another can fail its rebase (N13), which is safe. Nothing in the tests protects the concurrency block (N7).
- **Failure:** If the refresh fails, the job fails, `deploy` (via `needs`) is skipped, and nothing is committed. **OK** in the file as written; the tests do not protect it (N7).
