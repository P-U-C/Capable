# capable v2: code, security and reliability review

Reviewer: independent. Clone `/tmp/review-code` at `8ebfc8a`. Nothing in the repo was changed. Probes and mutation scripts are in `/tmp/review-code-scratch/{probes,mut-tools}`.

## Verdict

The rendering core is solid. Every string reaches the DOM through the escaping `html` tag. URLs are checked twice (regex and `new URL`). The inline JSON escapes `<`. The CSP has no `unsafe-inline`. A contract-valid hostile App ran in headless Chrome with no dialogs, no `src=` and no non-https hrefs. Ingest is deterministic: two `--offline` runs produced byte-identical output, and the editor's in-place offline run changes nothing. All suites and both gates pass.

The weak spots are in the pipeline around the app:
- **One creator's display name can stop every refresh permanently.** A bidi isolate character in the name gets through ingest cleaning but fails the contract.
- **Editor deploys can be lost.** The single concurrency group cancels a pending push deploy, and the scheduled run that replaces it skips deploy.
- **Two writers commit `content/build/app.json`.**
- **Hub nodes are fully trusted.** Nothing verifies signatures, and the first node to answer is the only source of truth.
- **Any https `.m3u8`/`.mp4` host can supply an autoplaying lead video.**
- **The Google Fonts stylesheet blocks first paint.** Measured: first contentful paint goes from 128 ms to 4128 ms when that stylesheet is 4 s late.
- **hls.js loads from all of cdnjs with no SRI.**
- **The contract validator has many gaps and no tests of its own.**
- **The DOM half of the app (view-deck, main) has no behavioural tests.** Progress recording and video cleanup can be deleted and no test fails.

No blocker. Fix S1, S2 and S4–S6 before relying on unattended updates.

Counts: **0 blocker · 7 major · 13 minor · 5 nit**.

## Findings

### Major

**S1: A creator's display name containing U+2066–U+206F stops every refresh, permanently.** Lane: ingest (planner to export the regex).
- **Where:** `ingest/src/text.mjs:8` (`CONTROL` strips U+2060–2064 but not U+2066–206F), `ingest/src/compile.mjs:92`, `ingest/src/compile-app.mjs:128-130` (`isDisplayName` checks only C0/C1), `contract/validate-app.mjs:161` (rejects U+2060–206F).
- **What happens:**
  1. The display name passes `plain()` and is stored in `book.people`, which is carried forward in every later book.
  2. When that person places, `compileApp` builds `creators[fid].displayName`.
  3. `validateApp` rejects it, and `compileApp` throws `CompileError`.
  4. `refresh` exits 1 on every run. Nothing is committed or deployed, with no end date.
- **Who can trigger it:** any entrant, by setting their name before submitting.
- **Repro:** `node /tmp/review-code-scratch/probes/displayname.mjs /tmp/review-code` prints `plain() keeps U+2067: true isDisplayName: true` and then `compileApp THROWS … app.creators.2391.displayName: … no control or format characters`.
- **Fix:**
  - Export one `FORMAT_CHARS` regex from the contract and use it in `isDisplayName`. Drop a bad name; never throw over it.
  - Widen `clean()` to cover U+2066–206F, U+061C, U+180E and U+2028–2029.
  - Add a test. Mutation M48, which removes bidi stripping from `clean()`, currently survives.

**S2: Editor publishes can sit undeployed for up to 24 h.** Lane: ingest.
- **Where:** `.github/workflows/refresh.yml:26-28` (one `concurrency: refresh` group for refresh and deploy) and `:67` (scheduled runs deploy only on change).
- **Timeline:**
  1. Scheduled run A is in progress.
  2. The editor pushes, and push run P is queued as pending.
  3. Scheduled run B is queued. GitHub cancels the pending P, because a group keeps only one pending run.
  4. In B, `book.json` is unchanged and the compiled App equals the editor's `app.json`, so `changed=false` and deploy is skipped.
- **Result:** the site stays on the pre-editor build until the next network change or the daily heartbeat.
- **Fix:** give deploy its own workflow or concurrency group, triggered by push and by `workflow_run`. Or make the scheduled deploy condition "head sha ≠ last deployed sha" (Deployments API) instead of `changed`.

**S3: Hub nodes are trusted without verification, and the first node to answer is the only source of truth.** Lane: ingest.
- **Where:** `ingest/src/node.mjs:128-141` and `ingest/src/refresh.mjs:138` (the only check is `m.data.fid === fid`).
- **What's missing:** there is no hash or Ed25519 signature check and no cross-node agreement. `haatz.quilibrium.com`, a third-party node, is queried first.
- **Forgery:** a malicious or compromised node can forge casts from watched fids 1 and 37. Fake prizes become draft lessons in the app. Fake results decide which video autoplays as the lead.
- **Lagging node:** if it answers `200 {"messages":[]}` for a thread it hasn't synced (the stub and real hubs answer this way), the thread counts as "complete". `refresh.mjs:246-252` then drops every carried non-seed entry, and their works disappear from the app. Node order is fixed, so this repeats on every run.
- **Fix:**
  - Verify `hash` (BLAKE3 of the data bytes) and `signature` for prize and results casts. At minimum, require a second node's `castById` to agree for prize/results casts and before any deletion.
  - Never drop an entry that a results post references on the word of one node.

**S4: Lead videos may come from any https host, and they autoplay.** Lane: ingest (allow-list), app (CSP).
- **Where:** `ingest/src/compile-app.mjs:56-63`: any `*.m3u8` or `*.mp4` URL on any host becomes `video.hls`/`video.mp4`. CSP `media-src … https:` and `connect-src 'self' https:` are at `app/build.mjs:38-39`.
- **Risk:** a placed creator who controls the server can:
  - swap the clip after judging (it autoplays to every reader with our credit on it);
  - log readers' IPs;
  - serve a very high bitrate.
- **Fix:** allow-list stream hosts (`stream.farcaster.xyz`, `stream.warpcast.com`, …) for `hls`/`mp4`; anything else becomes `external`, a link out. Then narrow `media-src`/`connect-src` to those hosts.

**S5: The Google Fonts stylesheet blocks first paint.** Lane: app.
- **Where:** `app/build.mjs:27-28` and `:152`. The `<link rel=stylesheet>` to fonts.googleapis.com is render-blocking and pulls 5 families and 8 faces. Cross-origin, so the SW never caches it.
- **Measured** in headless Chrome at 390×844 (`probes/fcp.py`):

  | Fonts CSS answers after | First contentful paint |
  |---|---|
  | 0 s | 128 ms |
  | 4 s | 4128 ms |

  On a network that drops or blackholes Google (captive portals, some countries and corporate networks), first paint waits for the connection timeout on every cold start.
- **Fix:** self-host subsetted woff2 files in `dist` (precached, cache-first) and preload one or two critical faces. Or at least inject the Google `<link>` from `main.mjs` so it doesn't block; the CSP already allows it.

**S6: hls.js has no SRI, and `script-src` allows all of cdnjs.** Lane: app.
- **Where:** `app/src/player.mjs:10, 34-38` (no `integrity`) and `app/build.mjs:34` (`script-src 'self' https://cdnjs.cloudflare.com`).
- **Risk:** a cdnjs compromise or a swapped file means script execution in the app. The whole-host allowance also enables the known cdnjs CSP-bypass gadgets (old AngularJS and others) if any HTML injection ever lands.
- **Fix:**
  - Set `s.integrity = "sha384-…"` for 1.5.20; `crossOrigin` is already `anonymous`. The sandbox could not reach cdnjs to compute the hash.
  - Narrow `script-src` to the exact file URL.
  - Or vendor hls.js as a lazy same-origin chunk.

**S7: The DOM layer has no behavioural tests.** Lane: app.
- **Where:** `app/src/view-deck.mjs`, `main.mjs`, `view-home.mjs` and `gesture.mjs` are only grepped as source (`app/test/deck.test.mjs:232-234`).
- **Survivors:**

  | Mutation | Deleted behaviour |
  |---|---|
  | M59 | `store.visit` (`view-deck.mjs:124`): progress is never saved |
  | M42 | pausing the previous video on swipe (`:87`): audio keeps playing from a hidden card |
  | M60 | player destroy on leave |
  | M56 | the unknown-deep-link fallback (`main.mjs:26`) |

- **Fix:** a small fake-DOM or local Playwright smoke test (no network) that mounts a deck, swipes, and asserts that `citizen.v1` changed, the previous player paused, and players were destroyed on `#/`.

### Minor

**S8: The contract validator accepts App content that breaks or embarrasses the app, and crashes on some inputs.** Lane: planner.
- **Accepted** (`probes/validator.mjs`, all with `--strict`):
  - `build.repo: "javascript:alert(1)"` next to a valid `site`. `validate-app.mjs:121-124` checks only `.some`; video checks every key.
  - `lessons: []`.
  - Trait name `"Prize Winner"` + 5000 chars. Shown on home: `hostile_trait_names_on_home: ["Prize Winner", …]`. `app.name: "Bounty"`, `citizen.name: ""`. There is no BANNED or length check on `app.name`, `citizen.name` or `traits[].name` (`:135-143`).
  - Duplicate trait ids.
  - A 5000-char source title containing `<b>`. Title and author have no length limit and no `validateText` (`:53-54`).
  - RLO (U+202E) and ZWSP in lesson text. `validateText` (`:15-24`) has no format-character rule.
  - A single 1100-char word.
  - The same work id twice; two lessons on one topic (the same videos appear twice); a work whose `fid` has no creator.
  - A draft with no idea card. The spec requires ≥ 1; `:88` checks only the work slots.
- **Throws TypeError instead of returning errors:**
  - card `type: "constructor"`: `CARD_RULES[c.type]` reads up the prototype chain (`:79`);
  - `creators: {"1": null}` (`:160`);
  - `sources: {}` (`:100`).
- **Fix:**
  - Use `Object.hasOwn`.
  - Apply `validateText` (with a max length) to the name fields.
  - Add a format-character regex for all text, a maximum word length (~40), and unique trait ids, work ids and topics.
  - Require ≥ 1 idea card in drafts and per-key https checks on `build`.
  - Add `contract/test/`. Contract survivors: M20 (HTML rule), M21 (duplicate ids), M22 (unknown trait), M36 (per-key video https), M44 (exactly one counter), M55 (slug ids), M61 (one trait card), M62 (sorted and unique numbers).

**S9: Two writers commit `content/build/app.json`.** Lane: ingest + planner (runbook).
- **Where:** `refresh.yml:56-61` and `docs/REFRESH-PROMPT.md` step 6.
- **Failure modes:**
  - (a) Refresh checks out at S, the editor pushes E, refresh commits and runs `git pull --rebase` → conflict on `app.json`. The run fails, with no retry.
  - (b) Non-overlapping hunks auto-merge into a hybrid JSON that is then deployed.
  - (c) The editor's head check is followed by `push_files`. A refresh commit can land in between, and the editor's older `app.json` (compiled from the older `book.json`) overwrites the fresher one.
- All three heal on the next run.
- **Fix:** commit only sources from the editor (lessons, `works.json`). Have the deploy job compile `app.json` (`refresh.mjs --offline`) before `npm run build`. On a refresh push conflict: fetch, reset, recompile, retry.

**S10: In-app updates ignore editor publishes.** Lane: ingest/planner (runbook), app.
- **Where:** the runbook compiles with `--now <book.generatedAt>`, so `app.json.generatedAt` doesn't change. `app/src/data.mjs:24` requires a strictly newer `generatedAt`.
- **Probe:** edited a lesson promise and recompiled. `generatedAt` stayed `19:58:07Z` and `acceptUpdate(...).changed === false`. A resumed standalone PWA never shows the edit until a full reload.
- **Fix:** compare a content hash (`sameApp`) rather than time, or bump `generatedAt` when the App changes.

**S11: Reading a draft marks the later full lesson as finished.** Lane: app.
- **Where:** `app/src/store.mjs:26-33` records `done` for drafts too. `model.mjs:26-33` counts `done[id]` for ready lessons. The runbook lets the editor keep the draft's id.
- **Probe** (`probes/draftdone.mjs`): after reading a 5-card draft, then shipping the ready lesson under the same id, the trait shows `civil 1/2 done` although the reader never opened the full lesson.
- **Fix:** record `done` only when `lesson.status === "ready"`, or key `done` by id plus a card-content hash.

**S12: Saved positions and ticks are card indexes, so they shift when cards change.** Lane: app.
- **Where:** `pos` is an index into the expanded deck (`deck.mjs:85`, `view-deck.mjs:124`). Tick keys are `practice-<index in lesson.cards>` (`deck.mjs:36`, `cards.mjs:121`).
- **Effect:** when results arrive and lead/more cards are inserted, or the editor edits a lesson, readers resume on a different card and ticks attach to the wrong step.
- **Fix:** store the card key (`type`+`ord`). Key ticks by practice `ord` and step index plus a text hash.

**S13: Visiting any in-scope URL replaces the offline shell.** Lane: app.
- **Where:** `app/lib/sw.mjs:50, 29`. Every in-scope navigation response is cached as `./index.html`.
- **Probe** (`probes/swpoison.py`): visit `/Capable/manifest.webmanifest`, go offline, open `/Capable/`. The page is `application/manifest+json | {"name": "capable", …`.
- **Also:** the install `addAll` (`:14`) goes through the HTTP cache (Pages sends `max-age=600`), so a new SW can precache a stale `index.html`/`app.json`.
- **Fix:** cache a navigation only if its path is the scope or `index.html` and its content type is `text/html`. Precache with `new Request(u, {cache: "reload"})`.

**S14: Video uses a lot of data on phones.** Lane: app.
- **Where:** `view-deck.mjs:86-90`, `player.mjs:122-124, 143, 176-179`.
- **What happens:**
  - Lead videos autoplay as soon as their card is active.
  - `pause()` doesn't call `hls.stopLoad()`, so hls.js keeps filling its 20 s buffer after a swipe-past.
  - `startLevel: -1` with `capLevelToPlayerSize` can pick 1080p on 3× DPR phones.
  - `loop: true`; `saveData` is ignored.
  - Players live until the deck closes.
- **Fix:** tap-to-play when `navigator.connection?.saveData`. Call `stopLoad()`/`startLoad()` on pause/play. Cap the level for autoplay. Destroy players more than one card away.

**S15: The workflow could be hardened against supply-chain attacks.** Lane: ingest.
- **Tags, not SHAs:** actions are pinned by tag (`refresh.yml:39,42,78,81,86,90`), and the test requires tags (`ingest/test/refresh.test.mjs:360`).
- **Build runs with deploy permissions:** the deploy job runs `npm ci` (esbuild postinstall) and the tests while holding `pages: write` + `id-token: write` (`:70-85`).
- **Token on disk:** checkout persists the token. The `contents: write` token sits in `.git/config` while refresh parses network data.
- **Fix:**
  - Pin actions by SHA (with a `# v5` comment).
  - Split into a build job with no permissions (it uploads the Pages artifact) and a deploy job that only runs `deploy-pages`.
  - Set `persist-credentials: false` and pass the token only in the push step.
- No injection found: no `${{ }}` appears inside `run:`.

**S16: The editor pushes straight to main with broad credentials.** Lane: planner (docs).
- **Where:** `docs/REFRESH-PROMPT.md` step 6 uses `push_files` to `main`. There is no PR and no required check. The path restriction exists only in the prompt.
- **Exposure:** the editor reads network-derived text in `book.json`: headlines and prize text, plus generated glosses and names built from repo and host names. A confused or injected session can write any path, workflows included, and the connector may reach other repos.
- **Fix:** have the editor open a PR from a bot branch. Protect `main` with required checks (S17). Use a token scoped to this repo.

**S17: CI never validates lesson files, and one bad lesson stops all refreshes.** Lane: ingest.
- **Where:** push runs only test and build the app, which checks `app.json` non-strict (`refresh.yml:84-85`). `compileApp` throws on the whole App if one lesson is invalid (`compile-app.mjs:273-274`).
- **Effect:** a pushed lesson with a duplicate `number`/`id` or an unknown trait stops every scheduled refresh, silently, until someone fixes the file.
- **Fix:** on push, run `node contract/validate-app.mjs --strict content/lessons/*.json` and the ingest tests. In `compileApp`, drop an invalid lesson with a warning, matching SWARM's "dropped and counted" rule.

**S18: Prototype-chain lookups crash compile.** Lane: ingest.
- **Where:** `compile-app.mjs:234`, `topics[p.id]`.
- **Probe** (`probes/proto.mjs`): a watched-fid headline "$1000 Prize for Constructor" makes `chapterIdFor` return `constructor`, and `compileApp` throws `TypeError id.replace is not a function` on every run.
- **Fix:** `Object.hasOwn(topics, p.id)`, or use a `Map`.

**S19: The node client is fragile under slow or huge responses.** Lane: ingest.
- **Body size:** `node.mjs:102` reads the whole body with `res.text()`. Only the 5 s timeout bounds it.
- **Slow first node:** there is no node demotion. A slow but alive first node costs 5 s on every request, across 3 cast pages × fids, 10 reply pages × prizes and up to 100 user lookups. The 15-minute job timeout is reachable.
- **Repeated lookups:** fids without a username are looked up again on every run (`refresh.mjs:19, 285`). 59 such fids exist now. The cap of 100, sorted by fid, means higher fids can be skipped forever. 3 of 8 creators currently show as "a creator".
- **Fix:** cap the body (Content-Length check plus a streamed byte counter). Demote a node for the rest of the run after a failure. Record when an unnamed fid was last looked up and retry daily.

**S20: Long unbroken strings overflow and are clipped.** Lane: app.
- **Where:** only `.shout` sets `overflow-wrap` (`app.css:90`).
- **Probe** (`probes/browser.py`, hostile build): the deeper card's 3000-char source title overflows by 37,688 px and is cut off. URLs or long words in other text cards behave the same way.
- **Fix:** `overflow-wrap: anywhere` on card text containers, plus S8's maximum word length.

### Nits

**S21: The build target says safari15, but the code needs Safari 16.** Lane: app.
- **Where:** `app/build.mjs:92`.
- **What's newer:** container units `100cqw` (`app.css:91`) need Safari 16. The bundled validator uses `Array.prototype.at` (`validate-app.mjs:90`), which needs 15.4; `acceptUpdate` throws there and the error is silently caught. `inert` needs 15.5.
- **Fix:** target safari16 or add fallbacks.

**S22: The CSP could be tighter.** Lane: app.
- It is delivered by meta tag, so `frame-ancestors` is impossible and the app can be framed. Pages can't send headers.
- `img-src` allows `https: data: blob:`, but no `<img>` is rendered.
- Consider `require-trusted-types-for 'script'` with a single policy in `html.mjs`. That would make "markup only via SafeHtml" a browser-enforced rule.

**S23: Caches and storage are shared across the whole Pages origin.** Lane: app.
- The `capable-*` cache names and the `citizen.v1` key are origin-wide.
- `p-u-c.github.io` is shared by every P-U-C Pages repo. A second deployment of this app (for example staging) deletes the other's caches on activate (`sw.mjs:20`).
- **Fix:** prefix cache names with `registration.scope`, or use a custom domain.

**S24: The gate writes to a fixed /tmp path.** Lane: planner.
- `scripts/gate.mjs:146-149` writes `/tmp/primer-gate-book*.json`, so parallel lanes on one host race. Use `mkdtemp`.

**S25: The runbook has the editor write planner-owned files.** Lane: planner.
- `docs/REFRESH.md` and `REFRESH-PROMPT.md` tell the editor to write `content/seed/works.json`, which `SWARM.md` and `gate.mjs` (`PLANNER_ONLY`) reserve for the planner.
- The lessons-lane gate knows only the four original files, so editor-written lessons have no lane or gate.
